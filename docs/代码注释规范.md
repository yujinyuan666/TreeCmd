# 代码注释规范（本项目约定）

> 目的：这套代码是**给人读的**。每个函数都要能回答两个问题：
> **「它是干嘛的」** 和 **「参数是什么东西」**。
> 读者假设是**Go 新手**：术语可以保留英文，但解释要能用大白话说清。

## 一、格式（统一照此写）

```go
// Foo 一句话说明它做什么（动词开头，中文，句末有句号）。
//
// 需要时补一段细节：关键约束 / 为什么这么写 / 调用前提 / 踩过的坑。
//
// 参数：
//
//	cfg   — 节点配置；必须是已经过 config.Load 校验的（里面的路径已解析为绝对路径）
//	write — true 表示真的落盘；false 只做演练，不写任何文件
//
// 返回：
//
//	*Config — 解析并校验后的配置
//	error   — 文件读不到 / 校验不过时返回；文案可直接给人看
func Foo(cfg *Config, write bool) (*Config, error) {
```

要点：

1. **首行以函数名开头**（Go 的 doc comment 惯例，`go doc` 会把它当摘要）。方法写**方法名**，不带接收者。
2. 有**接收者**时，先说明它代表什么（一句话），再写参数：
   ```go
   // Upsert 插入或更新一个直接子节点。
   //
   // 接收者 t 是直接子节点表（并发安全）。
   //
   // 参数：
   //
   //	c — 要写入的子节点；同 NodeID 已存在时按字段合并（不是整条替换）
   func (t *Table) Upsert(c *Child) {
   ```
3. **参数块**用 `//` + 一个 `tab` 缩进的行（`go doc` 会渲染成定义列表）。逐个说清：
   类型含义、单位、取值范围、`nil` / 空值 / 0 时会发生什么。
4. **返回值块**同理：说清什么情况下返回什么。没有返回值就省略该块；没有参数就省略参数块。
5. 简单到不需要解释的（如一行 getter）保持一行即可，不要为凑格式硬加段落。
6. **禁止**：写"// TODO"、写 emoji、写"参见某某函数"却没说明它是干嘛的。
7. 单行别超过 ~120 个字符（中文字符算 1 个）。

## 二、哪些文件不碰

- `internal/pb/*.go` —— **protoc 生成**，文件头写着 `DO NOT EDIT`，改了下次生成就丢。
- `api/proto/node.proto` —— 手写契约，但它自己有行内注释，保持原样。

## 三、改注释时的铁律

> 加注释**只许动注释**。标点、空行可以调整；**标识符、语句、导入、结构体字段、常量值一个字符都不能变。**

改完自检（在项目根目录）：

```bash
gofmt -l ./cmd ./internal      # 必须输出为空
go build ./...                 # 必须通过
go vet ./...                   # 必须通过
```

更硬的校验：比对"改动前 / 改动后"每个文件的 **token 哈希**。
哈希一致就说明**标识符、字面量、运算符序列一个都没变，变的只有注释** —— 这是批量加注释时唯一可靠的自我保护。

实现只要 20 行：用 Go 标准库 `go/scanner` 扫一遍文件，**丢掉 COMMENT token**，
把剩下的 `token 类型 + 字面量` 串起来取 sha256，逐个文件比对即可。

> ⚠️ 别用 `go/printer` 打印 AST 再取哈希 —— 它会把**空行与位置**也算进去，
> 注释一挪位置就误报"代码变了"（踩过这个坑）。

```bash
# 场景：先快照，再批量加注释，最后逐文件比对 token 哈希
cp -R treecmd /tmp/treecmd-before
tokhash /tmp/treecmd-before/treecmd > /tmp/a.txt
tokhash treecmd                    > /tmp/b.txt
diff /tmp/a.txt /tmp/b.txt          # 应当没有任何输出
```

## 四、读代码时怎么用这些注释

- `go doc -all ./internal/config` —— 把包内所有导出函数的注释按格式打出来，适合通读。
- `go doc ./internal/node Node.handle` —— 看单个函数的注释。
- 想从哪读起：见 `docs/项目功能完整介绍.md` 的「三条最短理解路径」。
