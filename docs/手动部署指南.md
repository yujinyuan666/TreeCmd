# 手工部署指南（单服务器、一个节点一个进程、证书由程序签发与续期）

面向的形态：**所有节点都部署在同一台服务器上**，每个节点一个进程、一份 `node.yaml`，
你手工放好配置后启动进程；**证书由程序签发与续期** —— 父节点给子节点（及其它客户端）签发走「运行期入网」，
换发新证走「运行期续签」；只有**根节点的自签材料**需要在部署时准备一次。

> **想快速上手，先读 `examples/README.md`**（三十秒速览 + 角色怎么判定 + 目录约定 + 字段生效时机 + 报错对照 + 检查清单），
> 再对着 `examples/node.yaml`（唯一一份权威样例：头部"按角色最简起步"，正文逐字段标了角色与默认值）填配置。
> 本文件是更长的运维手册，遇到具体问题时来查。

## 一、一个节点的目录长这样

```
<节点目录>/
├── node.yaml                     ← 你写的配置（唯一的配置文件）
├── keys/
│   ├── id_ed25519                身份私钥（必须预置，程序绝不生成）
│   ├── id_ed25519.pub            身份公钥（必须预置，与私钥成对）
│   └── ca                       （可选）本节点的 CA 私钥 —— 只有"还有下级"的中继需要
├── certs/
│   ├── node.crt                  身份证书链（自带，或由父在入网时签发写入）
│   └── node.crt.ca              （可选）本节点 CA 证书链 —— 中继需要，入网时由父签发写入
├── trust/                        信任锚目录：放 CA 证书（*.crt / *.pem 都会被加载）
├── enroll.token                  入网许可（内容与父端一致；权限 600）—— 仅子节点需要
├── node.log                      启动脚本写的日志
└── node.pid                      启动脚本写的 pid
```

**约定优于配置**：上面的路径都是默认值。你只写 `node.id` 与 `parents[]` 也能跑起来，
程序会按约定补全其余路径 —— 约定就是"相对 `node.yaml` 所在目录的默认路径"，下面逐项列着。

## 二、根节点：三件事

根节点没有父，**没有任何人能给根签发证书**（子节点可以走运行期入网向父换取），所以根的自签材料
必须在它**第一次启动之前**准备一次。仓库自带这个一次性脚本：

```bash
./scripts/init_root.sh /opt/treecmd/root <根节点ID>      # 例：0198f0c0-0000-7000-8000-000000000001
```

它一条命令产出：身份密钥对（调 `treecmd-node -genkey -with-ca`，格式与程序读取口径一致）、
自签 CA 证书（全树信任锚）、根的身份证书链、`certs/node.crt.ca`、`trust/root-ca.crt`、
`enroll.token`，最后自动自验（CN / 链 / CA 标记 / Ed25519）。
默认给根签 **3650 天**：根本身没有续签通道（续签是"父给子签"），给长期证书可以避免到期后全树失效。

下面这套 openssl 手工路径与它等价，想自己掌控细节就用它。

```bash
mkdir -p /opt/treecmd/root/{keys,certs,trust} && cd /opt/treecmd/root

# ① 生成密钥对（一次性；程序启动路径绝不生成密钥，这是显式的部署工具）
treecmd-node -genkey -keydir keys -with-ca

# ② 放好证书（根节点：用上面 openssl 自签的结果）
#    certs/node.crt      根的身份证书链（到根）
#    certs/node.crt.ca   根的 CA 证书链
#    keys/ca             根的 CA 私钥（用于给子节点签发；这是 ca_key_path 的默认约定）
#    trust/              放 CA 证书（信任锚）

# ③ 放好入网许可（子节点入网时要提交它）
printf '%s' "$(openssl rand -hex 24)" > enroll.token && chmod 600 enroll.token

# ④ 写 node.yaml（从唯一那份样例抄一份改；头部有"按角色最简起步"）
cp examples/node.yaml node.yaml
```

根节点 `node.yaml` 的关键项：

```yaml
node:
  id: ""                       # **可以留空**：根自带证书，程序会直接从证书取身份（ADR-050）
  name: root-sz-01             # 节点名：人类可读地标记"我是谁"（可省略，仅展示用途）
  remark: "深圳机房 · 根节点"    # 备注（可省略）
  listen: 127.0.0.1:19443      # 根要监听
security:
  ca_cert_paths: [trust]       # 信任锚目录
  ca_cert_path: certs/node.crt.ca
  ca_key_path: keys/ca
  enrollment:
    enabled: true              # 允许子节点入网（否则子节点拿不到证书）
    token_path: enroll.token
api:
  http_addr: 127.0.0.1:18443   # 提交指令 / 查结果 / 健康 / 指标
```

> 写不写 `id` 都行：写了就以它为准（必须与证书身份一致）；留空则从证书取 —— **程序绝不回写配置文件**。
> `node.name` / `node.remark` 只作展示：随注册上行（父端 `/v1/tree` 可见）、随健康响应逐跳回传
> （根在 `/v1/health` 能看到每个子节点的名字）。改完 `kill -HUP` 会主动重注册一次把它同步出去。

## 三、子节点：只需要"我是谁 + 父地址"

```yaml
# /opt/treecmd/child-01/node.yaml —— 全文就这些，其余按约定补全
node:
  id: ""                        # ✨ 留空即可：程序自动定 ID（见下），**绝不回写本文件**
  name: edge-sz-01              # 节点名（可省略）
  remark: "1 号柜 3 号机位"      # 备注（可省略）
parents:
  - id: <父的真实 NodeID>        # 父的真实 NodeID
    addr: 127.0.0.1:19443
```

> **`node.id` 留空的语义（ADR-050）**：按下列顺序取（前一个命中即停止，全程**只读**）——
> ① 配置里写了就用它；② 否则取**已签发证书的身份**；③ 否则取 `state.dat` 的 `self.id`；
> ④ 都没有就生成一个 UUIDv7，并**在上线前**写进 `state.dat`（不是 `node.yaml`），此后固定。
>
> 于是"新节点上线"不需要先手工编 UUID 再去签发证书：**留空 → 启动 → 拿 ID 向父入网换证**。
> 两条边界：① `state.dat` 与证书身份不一致 → 以**证书**为准并告警；
> ② 父端若用 `enrollment.allow_ids` 白名单，白名单要填"这个节点实际拿到的 ID" —— 首启后看启动日志
> （`node.id 未写定 → 本次生成 … node_id=<ID>`）或读 `state.dat` 的 `self.id`。

再来三步：

```bash
cd /opt/treecmd/child-01
treecmd-node -genkey -keydir keys                       # ① 本节点密钥对（中继加 -with-ca）
mkdir -p trust && cp <你的 CA 证书> trust/              # ② 信任锚
printf '%s' '<与父端一致的许可串>' > enroll.token && chmod 600 enroll.token   # ③ 入网许可
```

三样备齐就可以启动了 —— **证书不用你准备**，启动时它会向父入网申请：

```bash
./scripts/start_node.sh /opt/treecmd/child-01/node.yaml
```

> 中继节点（还有下级）额外需要一条 CA 私钥：`-genkey` 时加 `-with-ca`；
> 它的 **CA 证书**同样由父在入网时签发（写入 `certs/node.crt.ca`），你不用管。

## 四、运行期入网是怎么走的（子节点第一次上线）

```
子：EnrollChallenge ──► 父            # 父下发一次性 nonce（绑定 父ID + 子ID）
子：用自己的私钥签 (nonce|父ID|子ID)  # 私钥持有证明（PoP）
    连同 身份公钥(+CA公钥) + 入网许可 一起提交
父：校验 许可 / 白名单 / nonce 未用过 / PoP  → 用**自己的 CA 私钥**签这两个公钥
子：校验响应（身份是我、公钥与我的私钥匹配、链能到信任锚）
    → 原子写入 certs/node.crt（+ node.crt.ca）→ 热切换 → 正常 mTLS 握手 → 注册
```

要点：

- **私钥不出本机**：请求里只有公钥，响应里只有证书；程序既不生成也不接收私钥。
- **许可不是唯一门槛**：还要 PoP（拿不到私钥就签不出），所以 token 泄露也不能替别人申请证书。
- **父端两道策略**：`enrollment.token`（许可串）与 `enrollment.allow_ids`（白名单）。
  两者都配 = 双重校验；只配白名单 = 点名放行；**两者都不配 = 拒绝一切入网**（fail-safe）。
- **失败可自愈**：证书文件被删、节点重启后没证书、父还没起来 —— 都不会让进程退出，
  会按退避（1s→2s→4s…30s）持续重试；父起来后自动补上。
- **首启顺序无所谓**：子先起、父后起也能收敛（这正是单服务器手工启动最容易踩的场景）。

## 五、证书换发怎么生效

**第一次启动之后，证书不需要你管** —— 两条自动续期各管一半，互斥且互补：

| 谁 | 谁给它签 | 什么时候 | 代码路径 |
|---|---|---|---|
| 子节点 / 中继 | **它的父**（用父的 CA 私钥） | 剩余有效期 < 生命期 1/3 时，父在它 Connect / RESUME 时换发；子侧另有每小时调度主动请求 | `maybeOfferRenew` → `CertRenewOffer` → `applyCertRenew` |
| **根** | **它自己**（根自己的 CA 私钥） | 同一窗口；**另外：启动时若证书已进窗口（含已过期），先自签续期再启动** | `startSelfRenewLoop` / `resignSelfCert` |

两种都**只换证书、不换密钥、不换 CA** —— 已有背书链、origin 验签、CRL 条目全部照旧，别人也不用重新分发 `trust/`。
有效期口径（`internal/identity.issueCert`）：**身份证书 30 天**、**CA 证书 10 年**；续签窗口在生命期 2/3 处，
也就是**每约 20 天换一次**，而不是拖到最后几天才动手。

有父的节点**不许自签**（程序里 `canSelfRenew` 会拦住）：它的证书必须由父签发，自己签自己会破坏"父签发子"的授权模型。

当证书材料在进程外被替换时（例如你自己轮换了根的 CA），程序**只做"发现变更 → 重新加载"**，具体机制：

| 机制 | 说明 |
|---|---|
| 轮询兜底 | 默认每 `30s` 检查一次（`cert_reload.interval`，下限 5s）。检查只做 `stat`（size+mtime），**不读文件内容**；确认变了才读内容并重载 |
| 信号立即生效 | `kill -USR1 <pid>` 立刻检查一次 → 秒级生效（`scripts/start_node.sh reload` 就是这一条） |
| 监视范围 | 身份私钥 / 公钥 / 证书 + 本节点 CA 证书 / CA 私钥 + 全部信任锚（含目录）。可用 `cert_reload.paths` 显式指定 |
| 生效范围 | 信任锚与对端证书只影响**新连接**；**本节点身份证书/私钥**变了才会主动重连一次（`on_change: reconnect`）。想完全不打扰现有会话就设 `on_change: lazy` |
| 信任锚可给目录 | `ca_cert_paths: [trust]` —— 目录下所有 `*.crt`/`*.pem` 都是信任锚。**换 CA 时只替换目录里的文件，配置一行都不用改** |

**fail-safe（这条最重要）**：投放的证书只要**任何一项校验不过**（格式坏、身份不符、链不通、过期），
程序都会**继续用当前证书**并打一条 `ERROR`，绝不因为半个文件把正在跑的节点弄挂：

```
level=ERROR msg="cert reload: rejected new material, KEEPING current one (fail-safe)"
              err="REFUSE TO START: identity certificate ...: x509: malformed certificate"
```

对应的指标：`cert_reload_total{result="ok|failed|missing|nochange"}`。
`missing` = 证书文件被撤掉了（子节点会自动重新入网把文件补回来；根节点会继续用内存里的旧证书）。

## 六、启动脚本：起停 / 换证 / 热更

```bash
./scripts/start_node.sh <node.yaml>          # 启动（后台起，写 node.pid / node.log）
./scripts/start_node.sh status <node.yaml>   # 看状态
./scripts/start_node.sh stop   <node.yaml>   # 停止（SIGTERM，等 6s 再 KILL）
./scripts/start_node.sh reload <node.yaml>   # 换证后立即重载（= kill -USR1）
./scripts/start_node.sh conf   <node.yaml>   # 改了 node.yaml 的运行参数后热更（= kill -HUP）
```

启动不起来时脚本会把日志尾部直接打给你看 —— 原因就在那里（`load config failed` /
`node init failed: REFUSE TO START ...`）。

信号一览：

| 信号 | 作用 |
|---|---|
| `SIGUSR1` | **立即重载证书**（你的证书脚本换证后发它） |
| `SIGHUP` | 配置热更（只改运行参数段 → 原地热更；进 config_hash 的字段变了 → 触发全量重注册） |
| `SIGTERM` / `SIGINT` | 优雅退出 |

## 七、常用命令

```bash
treecmd-node -enroll -config node.yaml                   # 只做一次入网并写证书，然后退出
treecmd-node -genkey -keydir keys [-with-ca] [-force]    # 生成密钥对（一次性部署工具）
treecmd-node -config node.yaml -log-level debug          # 启动（debug 级日志）
```

命令面就这些：**没有"检查"子命令** —— 配置与身份材料的强校验就在启动路径上，任一条不过就报错退出，
把原因写清楚。配置本身的问题在**读配置**阶段就报（`load config failed`），身份材料的在**装配节点**阶段报
（`node init failed` + `REFUSE TO START`）；只有"证书暂缺"不算错，它是一条 WARN：

```
level=ERROR msg="load config failed" err="security.ca_cert_paths: trust: stat trust: no such file or directory（信任锚必须存在；给目录时会扫其中的 *.crt/*.pem）"
level=ERROR msg="load config failed" err="security.enrollment.token_path: stat enroll.token: no such file or directory"
level=ERROR msg="node init failed"  err="REFUSE TO START: identity private key keys/id_ed25519: open keys/id_ed25519: no such file or directory (私钥必须预置，程序绝不生成)"
level=WARN  msg="node up in ENROLLMENT mode（证书待签发）" role=leaf node_id=...
```

配置样例只有一份：`examples/node.yaml`（唯一权威）—— 头部给出**按角色最简起步**，
正文把**全部字段**连同"哪个角色需要 / 默认值 / 是否进 `config_hash`"逐条注释。

## 八、排错对照表

| 现象 | 原因 | 处置 |
|---|---|---|
| `REFUSE TO START: identity private key ...: no such file` | 没放私钥 | `treecmd-node -genkey -keydir keys` |
| `REFUSE TO START: identity public key ...` | 公钥缺失（或与私钥不成对） | 与私钥一并生成；不要手工改名 |
| `public key does not match private key` | 私钥/公钥不是同一对 | 重新生成一对，或放回配对的那一对 |
| `cert identity "..." != node id "..."` | 证书不是这个 `node.id` 的 | 放对证书；或删掉证书让程序重新入网 |
| `证书 ... 不存在，且未开启运行期入网` | 没证书又把入网关了 | 要么给证书，要么开 `enrollment.enabled` |
| `trust anchor dir ...: 目录里没有证书文件` | `trust/` 是空的 | 把 CA 证书放进 `trust/`（或在配置里显式给路径） |
| `ERR_ENROLL_BAD_PERMIT` | 子端许可与父端不一致 | 两边的 `enrollment.token` / `enroll.token` 改成一致 |
| `ERR_ENROLL_NOT_ALLOWED` | 父端 `allow_ids` 没包含这个 NodeID | 加上，或清空白名单并依赖 token |
| `ERR_ENROLL_NO_CA` | 父端没有 CA 私钥/证书 | 父端补 `ca_key_path` + `ca_cert_path`（根要自带） |
| `ERR_ENROLL_NO_PERMIT_POLICY` | 父端既没 token 也没白名单 | 二选一配上一个（这是刻意的 fail-safe） |
| 日志出现 `cert reload: rejected new material` | 投放的证书不合法 | 按 ERROR 里的原因修文件；**节点仍在正常服务** |
| `REFUSE TO START: ... certificate expired ...；证书已过期，而子节点的证书只能由父签发` | 子节点停机超过了证书剩余有效期（它自己签不了） | 挪走证书文件后启动（会走运行期入网重新换取），或让父端换发 |
| 日志出现 `证书已自签续期（根没有父，用自己的 CA 重签了一张）` | 根进入续签窗口时自己换了一张 | 不用处理：程序自己搞定了 |
| `cert reload: certificate file removed → will re-enroll` | 证书文件被撤掉 | 子节点会自动重新入网补回；根节点需重新投放 |
| 健康检查里子节点 `DEGRADED` | 该子节点正在重连 | 稍等再查；持续如此看它的日志与端口 |

## 九、上线检查清单

- [ ] `node.id` 是合法 UUIDv7，且与证书身份一致（子节点可暂缺证书）
- [ ] `keys/id_ed25519` + `id_ed25519.pub` 已就位，权限 600
- [ ] `trust/` 里有 CA 证书（换 CA 只换这里的文件）
- [ ] 子节点：`parents[].id` 是父的**真实 NodeID**（不是地址、不是路径）
- [ ] 子节点：`enroll.token` 与父端一致；中继还要 `keys/ca`（`-genkey -with-ca`）
- [ ] `node.yaml` 权限 600
- [ ] 每个节点都能启动成功（日志里没有 `REFUSE TO START` / `load config failed`）
- [ ] 起来了看一眼：`/v1/tree`、`/v1/health?depth=-1`、`/metrics`
- [ ] 证书脚本里加上换证后 `kill -USR1 <pid>`（或依赖 30s 轮询）
- [ ] 全树的镜像哈希一致：`curl -s localhost:18443/v1/tree` 里逐节点的 `build_hash` 应当相同，
      `lagging_children` 应当是 `0`

## 十、升级与回滚（可执行文件一致性）

**升级顺序：自上而下，只动根。** 每个节点启动时算一次自己可执行文件的哈希，子连上来时
第一件事就是跟父的比：不一致就自己拉取、校验、**原地重启**（PID 不变）。所以换版本这件事
只需要做一次 —— 换掉根的二进制。

```bash
# ① 换掉根的文件（换文件不影响在跑的进程：它跑的是内存里那份旧镜像）
cp 新版本/treecmd-node /opt/treecmd/root/bin/treecmd-node

# ② 重启根
./scripts/start_node.sh stop  /opt/treecmd/root/node.yaml
./scripts/start_node.sh start /opt/treecmd/root/node.yaml

# ③ 看着它自己往下传（lagging_children 从"子节点数"降到 0 就收敛完了）
curl -s localhost:18443/v1/tree | grep -o '"lagging_children":[0-9]*'
tail -f /opt/treecmd/relay/node.log | grep -E '可执行文件|原地重启'
```

中继与叶子会在各自重连时发现自己和父不一致，于是：

```
日志里会依次看到：
```

**回滚**同样是"只动根"：把根的二进制换回旧版并重启根，全树自动跟回来。

```bash
# 升级时程序会给上一版留一份 <可执行文件>.prev，直接用它最快
cp /opt/treecmd/root/bin/treecmd-node.prev /opt/treecmd/root/bin/treecmd-node
./scripts/start_node.sh stop  /opt/treecmd/root/node.yaml
./scripts/start_node.sh start /opt/treecmd/root/node.yaml
```

**不想让它自动动手时**：在根或任意节点上写

```yaml
selfupdate:
  on_mismatch: warn      # 只告警：日志与指标里报不一致，但不拉取、不重启
  # 或者整体关掉：
  # enabled: false
```

几个值得知道的细节：

- **一致时不产生任何额外动作**：只比一个字符串，不读盘、不发网络。
- **失败不会把节点弄挂**：拉取 / 落盘 / 替换任一步失败都只是打 ERROR 并继续用当前镜像服务；
  唯一会重启的路径是"替换成功"。
- **防重启循环**：同一个目标哈希在一个窗口内最多试 3 次（`max_attempts` / `attempt_window`），
  超了就锁住并在日志里告警。计数落在 `state.dat` 的 `self_update` 里 —— 因为重启会把内存清空。
- **暂存目录必须与可执行文件同文件系统**（默认就是它所在目录）：否则 rename 会退化成"复制"，
  就不是原子的了。
- **只对外发"自己启动时那份"**：如果磁盘上的文件在中途被换掉了，服务端会拒绝外发
  （`ERR_BINARY_LOCAL_CHANGED`），避免把半成品传下去。
- **只支持 unix**（重启手段就是 `syscall.Exec`）。
