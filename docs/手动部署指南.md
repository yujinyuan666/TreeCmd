# 手工部署指南（单服务器、一个节点一个进程、证书由程序签发与续期）

面向的形态：**所有节点都部署在同一台服务器上**，每个节点一个进程、一份 `node.yaml`，
你手工放好配置后启动进程；**证书由程序签发与续期** —— 父节点给子节点（及其它客户端）签发走「运行期入网」，
换发新证走「运行期续签」；只有**根节点的自签材料**需要在部署时准备一次。

> **想快速上手，先读 `examples/README.md`**（三十秒速览 + 角色怎么判定 + 目录约定 + 字段生效时机 + 报错对照 + 检查清单），
> 再对着 `examples/node.yaml`（唯一一份权威样例：头部"按角色最简起步"，正文逐字段标了角色与默认值）填配置。
> 本文件是更长的运维手册，遇到具体问题时来查。

## 一、一个节点的目录长这样

```
<节点目录>/
├── node.yaml                     ← 你写的配置（唯一的配置文件）
├── keys/
│   ├── id_ed25519                身份私钥（必须预置，程序绝不生成）
│   ├── id_ed25519.pub            身份公钥（必须预置，与私钥成对）
│   └── ca                       （可选）本节点的 CA 私钥 —— 只有"还有下级"的中继需要
├── certs/
│   ├── node.crt                  身份证书链（自带，或由父在入网时签发写入）
│   └── node.crt.ca              （可选）本节点 CA 证书链 —— 中继需要，入网时由父签发写入
├── trust/                        信任锚目录：放**你的父**的 `certs/node.crt.ca`（整份文件）。
│                                 只在**首次入网**需要 —— 入网成功后信任锚从自己的证书链自举
├── enroll.token                  **入网引导凭据**（父产出、整份拷过来；权限 600）—— 仅子节点需要
│                                 内容 = 入网许可 + 父的 CA 证书链（含父 CA 到根），一份顶两份
├── bin/
│   ├── treecmd-node              可执行文件（程序本体）
│   └── script/                   ★ 外部脚本目录（`<可执行文件所在目录>/script/`）
│                                 放"给 `type: script` 指令调用的脚本"。**只有根节点需要你放**：
│                                 其余节点执行前本地没有（或哈希不符）就会向父索取、校验、覆盖
├── node.log                      启动脚本写的日志
└── node.pid                      启动脚本写的 pid
```

**约定优于配置**：上面的路径都是默认值。你只写 `node.id` 与 `parents[]` 也能跑起来，
程序会按约定补全其余路径 —— 约定就是"相对 `node.yaml` 所在目录的默认路径"，下面逐项列着。

> **外部脚本这一项有个例外**：它的基准不是 `node.yaml` 所在目录，而是**可执行文件所在目录**
> （与自同步更新的暂存目录同一口径）。按上面的目录布局，脚本就放在 `bin/script/` 里；
> 目录不存在时启动会自动建一个空的。
>
> 两条必须知道的安全边界：
>
> - 脚本**以节点进程的身份运行，没有沙箱** —— 能读写本机任意文件、能联网。所以请只放你自己信任的脚本，
>   并知道信任边界是"谁能提交指令 + 谁能写这个目录 + 脚本哈希校验"。
> - 脚本名字走白名单（`[A-Za-z0-9._-]`），且服务端会拒绝符号链接逃出该目录 ——
>   否则 `{"script":"../../keys/id_ed25519"}` 就能把节点身份私钥当成脚本发出去。

## 二、根节点：三件事

根节点没有父，**没有任何人能给根签发证书**（子节点可以走运行期入网向父换取），所以根的自签材料
必须在它**第一次启动之前**准备一次。仓库自带这个一次性脚本：

```bash
cd /opt/treecmd/root && ./scripts/init_root.sh                                    # 最省：当前目录 + 自动生成 NodeID
./scripts/init_root.sh /opt/treecmd/root                                          # 指定目录，NodeID 仍自动生成
./scripts/init_root.sh /opt/treecmd/root 0198f0c0-0000-7000-8000-000000000001     # 想自己定 ID 就给第 2 个参数
```

参数**全都可以省**：节点目录默认是**当前目录**，根节点 ID 缺失时会现场生成一枚 UUIDv7
（口径与程序的 `identity.NewNodeID` 一致：48 bit 毫秒时间戳 + 版本位 7 + 变体位 10xx），直接写进证书 CN。
所以 `node.yaml` 里的 `node.id` **留空就行** —— 程序按「node.yaml → 证书身份 → state.dat → 新生成」
的顺序解析身份（ADR-050），证书一旦签发就是权威来源，它自己会读到这一枚。

它一条命令产出：身份密钥对（调 `treecmd-node -genkey -with-ca`，格式与程序读取口径一致）、
自签 CA 证书（信任链的顶端）、根的身份证书链、`certs/node.crt.ca`（**给直接子节点的投放物**）、
`trust/root-ca.crt`（根自己当锚用）、`enroll.token`（**入网引导凭据**：许可 + 根自己的 CA 链，
整份拷给每个子节点即可），最后自动自验（CN / 链 / CA 标记 / Ed25519）。
天数默认：**身份证书 30 天**（与程序给子节点签发的口径一致）、**CA 证书 3650 天**。根没有父可以给它
续签，所以程序会在"剩余不足生命期 1/3"时给它**自签续期**（首次启动之后就全自动了）；CA 证书给长期是因为
它是分发出去的信任锚，程序同样会用**同一把私钥**重签它（同密钥轮换，下级手里的副本照旧有效，不用重分发）。

下面这套 openssl 手工路径与它等价，想自己掌控细节就用它。

```bash
mkdir -p /opt/treecmd/root/{keys,certs,trust} && cd /opt/treecmd/root

# ① 生成密钥对（一次性；程序启动路径绝不生成密钥，这是显式的部署工具）
treecmd-node -genkey -keydir keys -with-ca

# ② 放好证书（根节点：用上面 openssl 自签的结果）
#    certs/node.crt      根的身份证书链（到根）
#    certs/node.crt.ca   根的 CA 证书链
#    keys/ca             根的 CA 私钥（用于给子节点签发；这是 ca_key_path 的默认约定）
#    trust/              放 CA 证书（信任锚）

# ③ 产出入网**引导凭据**（许可 + 根自己的 CA 链，一份文件给所有子节点）
#    根没有父，所以这一步得由脚本产出；中继则由它**自己**在入网后跑同一个脚本
../../scripts/make_bootstrap.sh "$(pwd)"

# ④ 写 node.yaml（从唯一那份样例抄一份改；头部有"按角色最简起步"）
cp examples/node.yaml node.yaml
```

根节点 `node.yaml` 的关键项：

```yaml
node:
  id: ""                       # **可以留空**：根自带证书，程序会直接从证书取身份（ADR-050）
  name: root-sz-01             # 节点名：人类可读地标记"我是谁"（可省略，仅展示用途）
  remark: "深圳机房 · 根节点"    # 备注（可省略）
  listen: 127.0.0.1:19443      # 根要监听
security:
  ca_cert_paths: [trust]       # 信任锚目录（根：放自己的 CA。子节点首次入网时放**父的** node.crt.ca）
  ca_cert_path: certs/node.crt.ca
  ca_key_path: keys/ca
  enrollment:
    enabled: true              # 允许子节点入网（否则子节点拿不到证书）
    token_path: enroll.token
api:
  http_addr: 127.0.0.1:18443   # 提交指令 / 查结果 / 健康 / 指标
  # 写接口的访问控制：本机(回环)免签；非本机必须带 HMAC 签名，没配密钥就一律拒绝。
  # 要远程运维就放 api.secret（见第十一节）；只在本机运维则**整段不用写**。
```

> 写不写 `id` 都行：写了就以它为准（必须与证书身份一致）；留空则从证书取 —— **程序绝不回写配置文件**。
> `node.name` / `node.remark` 只作展示：随注册上行（父端 `/v1/tree` 可见）、随健康响应逐跳回传
> （根在 `/v1/health` 能看到每个子节点的名字）。改完 `kill -HUP` 会主动重注册一次把它同步出去。

## 三、子节点：只需要"我是谁 + 父地址"

```yaml
# /opt/treecmd/child-01/node.yaml —— 全文就这些，其余按约定补全
node:
  id: ""                        # ✨ 留空即可：程序自动定 ID（见下），**绝不回写本文件**
  name: edge-sz-01              # 节点名（可省略）
  remark: "1 号柜 3 号机位"      # 备注（可省略）
parents:
  - id: <父的真实 NodeID>        # 父的真实 NodeID
    addr: 127.0.0.1:19443
```

> **`node.id` 留空的语义（ADR-050）**：按下列顺序取（前一个命中即停止，全程**只读**）——
> ① 配置里写了就用它；② 否则取**已签发证书的身份**；③ 否则取 `state.dat` 的 `self.id`；
> ④ 都没有就生成一个 UUIDv7，并**在上线前**写进 `state.dat`（不是 `node.yaml`），此后固定。
>
> 于是"新节点上线"不需要先手工编 UUID 再去签发证书：**留空 → 启动 → 拿 ID 向父入网换证**。
> 两条边界：① `state.dat` 与证书身份不一致 → 以**证书**为准并告警；
> ② `node.id` 留空时，程序会在**上线前**把它写进 `state.dat`；想知道它拿到了什么 ID，看启动日志
> （`node.id 未写定 → 本次生成 … node_id=<ID>`）或读 `state.dat` 的 `self.id`。

再来三步：

```bash
cd /opt/treecmd/child-01
treecmd-node -genkey -keydir keys                       # ① 本节点密钥对（中继加 -with-ca）
mkdir -p trust && cp <父的 certs/node.crt.ca> trust/    # ② 信任锚 = 你的**父**（不是根！整份文件）
cp <父目录>/enroll.token enroll.token && chmod 600 enroll.token   # ③ 父产出的引导凭据（许可 + 父的 CA 链）
```

三样备齐就可以启动了 —— **证书不用你准备**，启动时它会向父入网申请：

```bash
./scripts/start_node.sh /opt/treecmd/child-01/node.yaml
```

启动成功后，第 ② 步那份文件就可以删掉了（`security.ca_cert_paths` 也整段不必写）：
信任锚改由**本节点自己的证书链**自举 —— 链里本来就带着"父 CA → 祖父 CA → … → 根 CA"。
日志里会留下这一行，便于排错时解释"为什么没配锚也能连上父"：

```
信任锚来自自身证书链自举（未配置 security.ca_cert_paths）
```

**为什么是"父的 CA"而不是"根 CA"**：一条链能不能验通只看"能否接到**某个**信任锚"。
把父的整份 `node.crt.ca` 配进 `ca_cert_paths` 时，锚池里已经是 `[父CA, 祖父CA, …, 根CA]`
（加载器会把文件里的**整条链**都纳入），判定结果与"放根 CA"完全等价，但子节点从此不必认识根，
换父、换根都只影响它父那一层。这正是"**每个节点只对自己的父节点负责**"在部署上的落点。

> ⚠️ 必须放**整份文件**（含父 CA 一路到根）。只截取"父那一张"、漏掉根的话，
> **上级节点签发的跨跳委托（`ReqAuth`）在孙节点上会验不过** —— 那条链的末端是根。

> 中继节点（还有下级）额外需要一条 CA 私钥：`-genkey` 时加 `-with-ca`；
> 它的 **CA 证书**同样由父在入网时签发（写入 `certs/node.crt.ca`），你不用管。

## 四、运行期入网是怎么走的（子节点第一次上线）

```
子：EnrollChallenge ──► 父            # 父下发一次性 nonce（绑定 父ID + 子ID）
子：用自己的私钥签 (nonce|父ID|子ID)  # 私钥持有证明（PoP）
    连同 身份公钥(+CA公钥) + 入网许可 一起提交
父：校验 许可 / 白名单 / nonce 未用过 / PoP  → 用**自己的 CA 私钥**签这两个公钥
子：校验响应（身份是我、公钥与我的私钥匹配、链能到信任锚）
    → 原子写入 certs/node.crt（+ node.crt.ca）→ 热切换 → 正常 mTLS 握手 → 注册
```

要点：

- **私钥不出本机**：请求里只有公钥，响应里只有证书；程序既不生成也不接收私钥。
- **许可不是唯一门槛**：还要 PoP（拿不到私钥就签不出），所以 token 泄露也不能替别人申请证书。
- **父端只有一道策略：`enrollment.token`（入网许可）** —— 它是**唯一的授权判据**，没配它就拒绝一切入网。
  （曾经还有个 `allow_ids` 白名单，**已删除**：NodeID 是公开信息、与密钥对没有密码学绑定，
  "自报一个名单里的 ID + 自建一对密钥"根本挡不住。想限定"这次准入给谁"，正确做法是
  **每节点一枚一次性许可**，而不是给一份 ID 名单。）
  两者都配 = 双重校验；只配白名单 = 点名放行；**两者都不配 = 拒绝一切入网**（fail-safe）。
- **失败可自愈**：证书文件被删、节点重启后没证书、父还没起来 —— 都不会让进程退出，
  会按退避（1s→2s→4s…30s）持续重试；父起来后自动补上。
- **首启顺序无所谓**：子先起、父后起也能收敛（这正是单服务器手工启动最容易踩的场景）。

## 五、证书换发怎么生效

**第一次启动之后，证书不需要你管** —— 两条自动续期各管一半，互斥且互补：

| 谁 | 谁给它签 | 什么时候 | 代码路径 |
|---|---|---|---|
| 子节点 / 中继（身份证书） | **它的父**（用父的 CA 私钥） | 剩余有效期 < 生命期 1/3 时，父在它 Connect / RESUME 时换发；子侧另有每小时调度主动请求 | `maybeOfferRenew` → `CertRenewOffer` → `applyCertRenew` |
| 中继（**自己的 CA 证书**） | **它的父**（同一个窗口，但**只有子主动请求才会换** —— 父手上没有子的 CA 证书） | 子发现自己 CA 证书进窗口 → `CertRenewReq{want_ca}` + 提交当前那张 CA 证书证明"同一把密钥" | `handleCertRenewReq` → `reissueChildCA` → `ReissueCAFor` → `applyCACertRenew` |
| **根**（身份证书 + 自己的 CA 证书） | **它自己**（根自己的 CA 私钥） | 同一窗口；**另外：启动时若任一张已进窗口（含已过期），先自签续期再启动**。顺序是**先续 CA 证书、再用新 CA 证书重签身份证书**（反了会让"链里那张 CA"与磁盘上的不是同一张） | `startSelfRenewLoop` / `renewSelfCert` / `reissueForSelf` |

两种身份证书续签都**只换证书、不换密钥** —— 已有背书链、origin 验签、CRL 条目全部照旧。
**CA 证书轮换同样只换证书、不换密钥**：公钥不变 ⇒ 下级手里的旧 CA 证书在有效期内仍然有效、
**`trust/` 不用重新分发、下级也不用重新入网**。前提是"同一把密钥"，所以父端会校验子提交的
那张 CA 证书（IsCA / certSign / CN 含子 ID / 能接到本节点信任锚）。

有效期口径（`internal/identity.issueCert` → `issueCertWithSubject`）：**身份证书 30 天**、
**CA 证书 10 年**（两者都可用 `security.identity_cert_days` / `security.ca_cert_days` 覆盖，
默认值就是历史行为）；续签窗口在生命期 2/3 处，也就是**每约 20 天换一次**，而不是拖到最后几天才动手。

> ⚠️ **换 CA 密钥不在此列**：那是"真换 CA"，仍需全树重新分发 `trust/`。
> 轮换的是**证书**（同密钥）才不需要 —— 这也是"两个文件 `certs/ca.crt`（给下级的分发副本）
> 与 `certs/node.crt.ca`（本节点出示的 CA 证书）可以是两张不同证书、同一个 key"的原因。

有父的节点**不许自签**（程序里 `canSelfRenew` 会拦住）：它的证书必须由父签发，自己签自己会破坏"父签发子"的授权模型。

当证书材料在进程外被替换时（例如你自己轮换了根的 CA），程序**只做"发现变更 → 重新加载"**，具体机制：

| 机制 | 说明 |
|---|---|
| 轮询兜底 | 默认每 `30s` 检查一次（`cert_reload.interval`，下限 5s）。检查只做 `stat`（size+mtime），**不读文件内容**；确认变了才读内容并重载 |
| 信号立即生效 | `kill -USR1 <pid>` 立刻检查一次 → 秒级生效（`scripts/start_node.sh reload` 就是这一条） |
| 监视范围 | 身份私钥 / 公钥 / 证书 + 本节点 CA 证书 / CA 私钥 + 全部信任锚（含目录）。可用 `cert_reload.paths` 显式指定 |
| 生效范围 | 信任锚与对端证书只影响**新连接**；**本节点身份证书/私钥**变了才会主动重连一次（`on_change: reconnect`）。想完全不打扰现有会话就设 `on_change: lazy` |
| 信任锚可给目录 | `ca_cert_paths: [trust]` —— 目录下所有 `*.crt`/`*.pem` 都是信任锚。**换 CA 时只替换目录里的文件，配置一行都不用改** |
| 信任锚口径 | **是你的父，不是树的根**：放父的 `certs/node.crt.ca`（整份文件，含父 CA 到根）即可，**不需要从根拷任何东西**。而且只在**首次入网**需要 —— 入网成功后信任锚从本节点自己的证书链自举（`identity.ChainAnchors`），`trust/` 与 `ca_cert_paths` 都可以去掉 |

**fail-safe（这条最重要）**：投放的证书只要**任何一项校验不过**（格式坏、身份不符、链不通、过期），
程序都会**继续用当前证书**并打一条 `ERROR`，绝不因为半个文件把正在跑的节点弄挂：

```
level=ERROR msg="cert reload: rejected new material, KEEPING current one (fail-safe)"
              err="REFUSE TO START: identity certificate ...: x509: malformed certificate"
```

对应的指标：`cert_reload_total{result="ok|failed|missing|nochange"}`。
`missing` = 证书文件被撤掉了（子节点会自动重新入网把文件补回来；根节点会继续用内存里的旧证书）。

## 六、启动脚本：起停 / 换证 / 热更

```bash
./scripts/start_node.sh <node.yaml>          # 启动（后台起，写 node.pid / node.log）
./scripts/start_node.sh status <node.yaml>   # 看状态
./scripts/start_node.sh stop   <node.yaml>   # 停止（SIGTERM，等 6s 再 KILL）
./scripts/start_node.sh reload <node.yaml>   # 换证后立即重载（= kill -USR1）
./scripts/start_node.sh conf   <node.yaml>   # 改了 node.yaml 的运行参数后热更（= kill -HUP）
```

启动不起来时脚本会把日志尾部直接打给你看 —— 原因就在那里（`load config failed` /
`node init failed: REFUSE TO START ...`）。

信号一览：

| 信号 | 作用 |
|---|---|
| `SIGUSR1` | **立即重载证书**（你的证书脚本换证后发它） |
| `SIGHUP` | 配置热更（只改运行参数段 → 原地热更；进 config_hash 的字段变了 → 触发全量重注册） |
| `SIGTERM` / `SIGINT` | 优雅退出 |

## 七、常用命令

```bash
treecmd-node -enroll -config node.yaml                   # 只做一次入网并写证书，然后退出
treecmd-node -genkey -keydir keys [-with-ca] [-force]    # 生成密钥对（一次性部署工具）
treecmd-node -config node.yaml -log-level debug          # 启动（debug 级日志）
```

命令面就这些：**没有"检查"子命令** —— 配置与身份材料的强校验就在启动路径上，任一条不过就报错退出，
把原因写清楚。配置本身的问题在**读配置**阶段就报（`load config failed`），身份材料的在**装配节点**阶段报
（`node init failed` + `REFUSE TO START`）；只有"证书暂缺"不算错，它是一条 WARN：

```
level=ERROR msg="load config failed" err="security.ca_cert_paths: trust: stat trust: no such file or directory（信任锚必须存在：给文件就放父的 CA 证书链；给目录时会扫其中的 *.crt/*.pem）"
level=ERROR msg="node init failed"  err="REFUSE TO START: 待入网但没有任何信任锚（security.ca_cert_paths）：首次入网至少要给一份**父节点的 CA 证书链**…"
level=ERROR msg="load config failed" err="security.enrollment.token_path: stat enroll.token: no such file or directory"
level=ERROR msg="node init failed"  err="REFUSE TO START: identity private key keys/id_ed25519: open keys/id_ed25519: no such file or directory (私钥必须预置，程序绝不生成)"
level=WARN  msg="node up in ENROLLMENT mode（证书待签发）" role=leaf node_id=...
```

配置样例只有一份：`examples/node.yaml`（唯一权威）—— 头部给出**按角色最简起步**，
正文把**全部字段**连同"哪个角色需要 / 默认值 / 是否进 `config_hash`"逐条注释。

## 八、排错对照表

| 现象 | 原因 | 处置 |
|---|---|---|
| `REFUSE TO START: identity private key ...: no such file` | 没放私钥 | `treecmd-node -genkey -keydir keys` |
| `REFUSE TO START: identity public key ...` | 公钥缺失（或与私钥不成对） | 与私钥一并生成；不要手工改名 |
| `public key does not match private key` | 私钥/公钥不是同一对 | 重新生成一对，或放回配对的那一对 |
| `cert identity "..." != node id "..."` | 证书不是这个 `node.id` 的 | 放对证书；或删掉证书让程序重新入网 |
| `证书 ... 不存在，且未开启运行期入网` | 没证书又把入网关了 | 要么给证书，要么开 `enrollment.enabled` |
| `trust anchor dir ...: 目录里没有证书文件` | `trust/` 是空的 | 把**父的** `certs/node.crt.ca`（整份文件）放进 `trust/`，或在配置里显式给路径。⚠️ 已入网的节点要交给自举时，请**把 `trust/` 整个目录删掉**（并删掉 `ca_cert_paths`）—— 留一个**空目录**会被判成"配了锚却没有证书"而拒绝启动（刻意的 fail-fast） |
| `待入网但没有任何信任锚` | 首次入网（还没有证书）却没给锚 | 把**父的** `certs/node.crt.ca` 配进 `security.ca_cert_paths` —— 只要一份父的，**不需要根**；入网成功后这一项可以删 |
| `ERR_ENROLL_BAD_PERMIT` | 子端提交的许可与父端不一致 | 把**父产出的那份凭据**拷给子节点（多半是拿了别的父的凭据） |
| `ERR_ENROLL_NO_CA` | 父端没有 CA 私钥/证书 | 父端补 `ca_key_path` + `ca_cert_path`（根要自带） |
| `ERR_ENROLL_NO_PERMIT_POLICY` | **父端自己没配许可**（`enrollment.token` / `token_path`）⇒ 拒绝一切入网 | 用 `scripts/make_bootstrap.sh <父目录>` 产出凭据并配好 `token_path`（这是刻意的 fail-safe：入网认证只有许可一个口径） |
| 日志出现 `cert reload: rejected new material` | 投放的证书不合法 | 按 ERROR 里的原因修文件；**节点仍在正常服务** |
| `REFUSE TO START: ... certificate expired ...；证书已过期，而子节点的证书只能由父签发` | 子节点停机超过了证书剩余有效期（它自己签不了） | 挪走证书文件后启动（会走运行期入网重新换取），或让父端换发 |
| 日志出现 `证书已自签续期（根没有父，用自己的 CA 重签了一张）` | 根进入续签窗口时自己换了一张 | 不用处理：程序自己搞定了 |
| `cert reload: certificate file removed → will re-enroll` | 证书文件被撤掉 | 子节点会自动重新入网补回；根节点需重新投放 |
| 健康检查里子节点 `DEGRADED` | 该子节点正在重连 | 稍等再查；持续如此看它的日志与端口 |

## 九、上线检查清单

- [ ] `node.id` 是合法 UUIDv7，且与证书身份一致（子节点可暂缺证书）
- [ ] `keys/id_ed25519` + `id_ed25519.pub` 已就位，权限 600
- [ ] 首次入网的节点：`trust/` 里有**它自己父的** `certs/node.crt.ca`（整份文件；**不需要从根拷**）
- [ ] 入网成功的节点：`ca_cert_paths` 可整段不写（信任锚从自己的证书链自举，日志有对应一行）
- [ ] 子节点：`parents[].id` 是父的**真实 NodeID**（不是地址、不是路径）
- [ ] 子节点：`enroll.token` 是**它自己父**产出的那份引导凭据（许可 + 父的 CA 链）；中继还要 `keys/ca`（`-genkey -with-ca`）
- [ ] `node.yaml` 权限 600
- [ ] 每个节点都能启动成功（日志里没有 `REFUSE TO START` / `load config failed`）
- [ ] 起来了看一眼：`/v1/tree`、`/v1/health?depth=-1`、`/metrics`
- [ ] 对外 HTTP 的访问控制符合预期：启动日志里那行 `api auth:` 是你要的形态
      （`http_addr` 写了 `0.0.0.0` 又不需要远程运维 ⇒ 看到 WARN 是正常的，写接口只收本机请求；
      要远程运维就放 `api.secret`，见第十一节）
- [ ] 证书脚本里加上换证后 `kill -USR1 <pid>`（或依赖 30s 轮询）
- [ ] 全树的镜像哈希一致：`curl -s localhost:18443/v1/tree` 里逐节点的 `build_hash` 应当相同，
      `lagging_children` 应当是 `0`
- [ ] 要用 `type: script` 的话：**根节点的 `bin/script/` 里放好脚本**（`chmod 755`，
      首行写 shebang 指定解释器），其余节点不用管 —— 它们执行前会自己向父索取。
      提一句：脚本以节点身份运行、没有沙箱，只放自己信任的

## 十、升级与回滚（可执行文件一致性）

**升级顺序：自上而下，只动根。** 每个节点启动时算一次自己可执行文件的哈希，子连上来时
第一件事就是跟父的比：不一致就自己拉取、校验、**原地重启**（PID 不变）。所以换版本这件事
只需要做一次 —— 换掉根的二进制。

```bash
# ① 换掉根的文件（换文件不影响在跑的进程：它跑的是内存里那份旧镜像）
cp 新版本/treecmd-node /opt/treecmd/root/bin/treecmd-node

# ② 重启根
./scripts/start_node.sh stop  /opt/treecmd/root/node.yaml
./scripts/start_node.sh start /opt/treecmd/root/node.yaml

# ③ 看着它自己往下传（lagging_children 从"子节点数"降到 0 就收敛完了）
curl -s localhost:18443/v1/tree | grep -o '"lagging_children":[0-9]*'
tail -f /opt/treecmd/relay/node.log | grep -E '可执行文件|原地重启'
```

中继与叶子会在各自重连时发现自己和父不一致，于是：

```
日志里会依次看到：
  可执行文件与父不一致 self=92a15c47b0bd parent=e6f7d23081f0 parent_id=...
  开始自同步（镜像与父不一致） attempt=1 limit=3 target=e6f7d23081f0
  已向父申请它的可执行文件 want=e6f7d23081f0 staging=/opt/.../.staging
  父的可执行文件已收齐并校验通过 bytes=20247586 chunks=78 hash=e6f7d23081f0
  可执行文件已替换为新镜像，准备原地重启（连接会短暂中断，之后自动重连）
```

**回滚**同样是"只动根"：把根的二进制换回旧版并重启根，全树自动跟回来。

```bash
# 升级时程序会给上一版留一份 <可执行文件>.prev，直接用它最快
cp /opt/treecmd/root/bin/treecmd-node.prev /opt/treecmd/root/bin/treecmd-node
./scripts/start_node.sh stop  /opt/treecmd/root/node.yaml
./scripts/start_node.sh start /opt/treecmd/root/node.yaml
```

**不想让它自动动手时**：在根或任意节点上写

```yaml
selfupdate:
  on_mismatch: warn      # 只告警：日志与指标里报不一致，但不拉取、不重启
  # 或者整体关掉：
  # enabled: false
```

几个值得知道的细节：

- **一致时不产生任何额外动作**：只比一个字符串，不读盘、不发网络。
- **失败不会把节点弄挂**：拉取 / 落盘 / 替换任一步失败都只是打 ERROR 并继续用当前镜像服务；
  唯一会重启的路径是"替换成功"。
- **防重启循环**：同一个目标哈希在一个窗口内最多试 3 次（`max_attempts` / `attempt_window`），
  超了就锁住并在日志里告警。计数落在 `state.dat` 的 `self_update` 里 —— 因为重启会把内存清空。
- **暂存目录必须与可执行文件同文件系统**（默认就是它所在目录）：否则 rename 会退化成"复制"，
  就不是原子的了。
- **只对外发"自己启动时那份"**：如果磁盘上的文件在中途被换掉了，服务端会拒绝外发
  （`ERR_BINARY_LOCAL_CHANGED`），避免把半成品传下去。
- **只支持 unix**（重启手段就是 `syscall.Exec`）。

### 自查这几行

```bash
# ① 启动日志里就有一行（hash / 字节数 / 版本 / 路径）
grep '本节点可执行文件' /opt/treecmd/root/node.log
#   time=... level=INFO msg=本节点可执行文件 node=0198f0c0 hash=92a15c47b0bd bytes=20247586 version=v2 path=/opt/treecmd/root/bin/treecmd-node

# ② 拓扑里每个节点跑的是哪份镜像、有没有落后的
curl -s localhost:18443/v1/tree | grep -o '"build_hash":"[0-9a-f]*"\|"lagging_children":[0-9]*'

# ③ 指标
curl -s localhost:18443/metrics | grep -E 'binary_info|binary_size_bytes|selfupdate_lagging_children'
```

指标（`GET /metrics`）：`selfupdate_total{result=...}`（match / mismatch / synced / settled /
pull_failed / install_failed / locked …）、`selfupdate_serve_total{result=...}`、
`binary_info{hash=...}`、`selfupdate_lagging_children`。

## 十一、对外 HTTP 的访问控制（要远程运维时才需要配）

先说清楚这条边界：**HTTP 写接口不是"能连上就能调"**。`api.http_addr` 允许写成 `0.0.0.0`，
而 `POST /v1/crl`（吊销节点）、`POST /v1/forget`（清注册状态）、`POST /v1/commands`（让子树干活）
都是不可逆或影响面很大的动作 —— 所以非本机来源的写请求必须带共享密钥的签名。
实现与完整口径见 README「访问控制：写接口的本机豁免与远程签名」，这里只讲**部署怎么做**。

**默认形态（什么都不用配）**：写接口只接受来自本机（回环地址）的请求。你在服务器上 `ssh` 进去、
`curl localhost:18443/...` 照常可用；局域网里别人**调不动**这些接口（403）。启动日志会这么写：

```
level=WARN msg="api auth: 监听地址对外可达，但没配 api.auth.secret(_path) —— 非本机来源的**写请求会被一律拒绝**（403）…"
```

**要远程运维（从你办公机调 API）**：三步。

```bash
# ① 在节点目录里生成共享密钥（权限 600；它等价于"能执行写接口的凭据"，别进版本库）
head -c 32 /dev/urandom | base64 > /opt/treecmd/root/api.secret
chmod 600 /opt/treecmd/root/api.secret

# ② 让节点采纳它。**什么都不用改**：节点目录里存在 api.secret 就会被自动采纳
#    （与 enroll.token 同一个约定）。想显式声明就写：
#      api:
#        auth:
#          secret_path: api.secret
./scripts/start_node.sh conf /opt/treecmd/root/node.yaml   # 其实连 SIGHUP 都不用：密钥是请求时现读的

# ③ 把 api.secret 整份拷到运维机，用签名工具调（本机也能用，服务端照验）
git clone <repo> && cd treecmd
#   --audience **必填**：签名要声明"签给哪个节点"（node.yaml 的 node.id），
#   否则服务端以 ERR_API_AUTH_AUDIENCE 拒绝 —— 它就是防"把签好的请求转发给别的节点再执行一次"的
export TREECMD_API_AUDIENCE=0198f0c0-0000-7000-8000-0000abc00002
scripts/api_call.py --host 10.0.0.5:18443 --secret-file ./api.secret \
    POST '/v1/forget?node=<GUID>&mode=stale'
scripts/api_call.py --host 10.0.0.5:18443 --secret-file ./api.secret '/v1/tree'   # 读接口本就不设防
```

**④ 要跨不可信网络（办公网 → 机房 / 公网）：开 `api.tls`。** 明文 HTTP 上共享密钥只解决"谁有权
动手"，解决不了窃听与响应伪造 —— 中间人可以随手编一个 `{"status":"OK"}` 让你以为指令执行了。

```yaml
api:
  http_addr: 0.0.0.0:18443
  tls:
    cert_path: certs/api.crt    # 服务端证书（含链）
    key_path:  certs/api.key    # 私钥，权限 600
    require: true               # 明文请求一律拒绝（**含回环**：挡 TLS 终止型反代回源的那条路）
    # 走 mTLS（客户端也出示证书）时再加：
    # ca_path: certs/api-ca.crt
    # client_auth: require
    # 只在"证书即身份、不想再管共享密钥"时才加 trust_client_cert: true
```

```bash
# 自签一套（私有 CA 或单张自签都行；SAN 要写对，客户端靠它校主机名）
openssl req -x509 -newkey rsa:2048 -keyout certs/api.key -out certs/api.crt \
  -days 365 -nodes -subj "/CN=treecmd-api" -addext "subjectAltName=IP:10.0.0.5,DNS:api.example.internal"

# 客户端：--tls 会自动带上通道绑定（服务端证书哈希），并校验响应签名
scripts/api_call.py --host 10.0.0.5:18443 --secret-file ./api.secret --tls \
    --cafile ./api.crt POST '/v1/forget?node=<GUID>&mode=stale'
```

证书是**热重载**的（同 `internal/identity` 那套：改文件后下一个握手就用新的），换证书不用重启。

**换密钥**：直接覆盖 `api.secret` 即可 —— 密钥不进 `config_hash`、也不缓存在内存里（每个请求现读文件），
所以**既不用重启、也不用 SIGHUP**，下一个请求就用新的。

**四条必须知道的边界**：

1. **回环豁免看的是 TCP 对端地址**，而这个地址会被部署形态改写：API 端口前面挂了本地反向代理
   （nginx / socat / `ssh -L` / frpc / `kubectl port-forward`）时，所有请求的对端都变成 `127.0.0.1`。
   对此有两道闸，按需要选一个：
   - 带 `Forwarded` / `X-Forwarded-For` / `X-Real-IP` / `Via` 的请求**不再免签**（正常代理都会加这些头，
     本机 `curl` 不会）⇒ 默认形态下"反代绕过"就已经不成立；
   - 确需让代理后面的本机请求继续免签，把代理地址写进 `api.auth.trusted_proxies`
     （如 `["127.0.0.1/32"]`），之后按 RFC 7239 从右往左剥可信跳取真实来源，不是回环就照常要签名；
   - 最省心的写法是直接 `loopback_bypass: false`（本机也必须签名）。
2. **签名要声明接收方**（`--audience` / `X-Treecmd-Audience`）：防重放的 nonce 表是每节点一份的，
   所以签给 A 的请求被转发给共享同一密钥的 B 时会被**再执行一次**。
3. **明文 HTTP** 解决不了窃听与响应伪造（局域网里能抓包的人可以复用签名，但有 ±60s 时间窗与
   nonce 去重，抓到的重放会被拒）。跨不可信网络请开 `api.tls` + 通道绑定。
4. **`protect_reads: true` 会把读接口也纳入**（含 `/metrics`）。Prometheus 抓取这类场景抓不到签名，
   更省事的做法是让 Prometheus 走本机或 TLS 隧道，别直接暴露。
   `/v1/healthz` 是**永远免认证**的存活探针，可以用它做外部健康检查。

自检：`curl -s -o /dev/null -w '%{http_code}\n' -XPOST http://127.0.0.1:18443/v1/forget?all=1` 应当是 `200`
（本机豁免）；把同样的请求打到**对外地址**上应当是 `403` / `401`（离不掉签名）。端到端验收：
`test/api-auth.sh`（49 项断言，含错密钥 / 过期时间戳 / 重放 nonce / audience 不符 / 伪造转发头 /
缺通道绑定六类拒绝）。
